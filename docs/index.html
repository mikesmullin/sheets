Stage Contract

One .coffee file per column. A gate predicate decides when a cell may run; reduce does the work and returns a patch over a deep-frozen entity, shallow-merged two levels deep. reduce may do real I/O — files, network, LLM calls with live tools. Capabilities arrive through ctx.

§01mental model

Rows × Columns → Jobs

Rows are entities (db/<id>.yaml or db/<Class>/<id>.md). Columns are stages. A selection is a set of (entity × stage) jobs. Play enqueues them; the engine runs them under a concurrency gate.

Authoritative — YAML/Markdown on disk. PGlite under .sheets/pgdata is a disposable mirror for windowing, search and sort.
Durable — every attempt writes .sheets/runs/<ts>-<id>-<stage>.yaml with status, patch/error, logs, model & tokens.
You don't have to write stages by hand. Angela is an agent instance trained to implement stage code on demand — describe a column in one sentence and she writes the .coffee file against this contract. Her system prompt imports this very page, so she is working from the same guide you are.

Not to be confused with the angela harness — the dependency that powers the Sheets chat UI itself, and the instance's namesake. One is the runtime; the other is a character running on it.
§02entity & activity schema

What a row is, what a column is

Entity — one file per row

A database is just a directory of entity files. Two shapes load as-is: flat db/<id>.yaml, and db/<Class>/<id>.md, whose frontmatter is parsed as the document while the Markdown body is preserved untouched on write. Fields live in a two-level component → field map. An entity does not carry its own id — the filename is the id, which is why ctx.entityId exists (§08).

db/<id>.yaml
produce:
  name: 'Blood orange'
appearance:
  color: '#c0392b'
shipping:
  destination:
    warehouse: 'east-dock'    # nested values are fine; patches reach them by dotted key

Activity — one worksheet tab

An activity at .sheets/activities/<slug>.yaml names an entity source and an ordered column list. rows.source resolves against the workspace root but may be absolute, so one server can front several databases as separate tabs while its own config stays in ./.sheets.

.sheets/activities/sheet1.yaml
title: Produce
rows:
  source: db            # any directory of entity files; absolute paths allowed
columns:
  - field: produce.name         # displays/edits one field — NOT playable
  - stage: fruit-color          # executable stage column
  - stage: average-volume
ColumnFormBehavior
Field{field: 'component.field'}Displays and edits one value. It has no reduce, so it is not playable.
Stage{stage: '<slug>'}Executable. Resolves to .sheets/stages/<slug>.coffee (§03).
A1 coordinates are ephemeral. A range like B3:D4 is resolved at enqueue time against the activity's ordered columns and the row-ordered entity ids — it is never stored as a column's identity. Reorder or hide columns and the same letters address different stages. A range is a selection gesture, not a reference.
§03file & naming

Where stages live

Path.sheets/stages/<slug>.coffee — one file per stage
Activity ref.sheets/activities/<activity>.yaml → columns: [{stage: <slug>}] (no .coffee suffix)
Slug/^[a-z0-9-]+$/ recommended; derived from prompt via promptStageSlug in src/server.coffee
CompiledCoffeeScript → ESM via src/stages.coffee; cached by mtime; served to the browser as /stagemod/stages/<slug>.mjs
Imports: allowed, with one rule. Stages may import from .sheets/lib/*.mjs — both loaders use real URLs, and src/stages.coffee version-stamps from '../lib/*.mjs' specifiers so edits hot-reload. The rule is who evaluates what: the browser imports the whole stage module to render a cell, so anything statically imported must be browser-safe. One node:fs in a lib five levels down blanks the entire column with a CORS error. Load server-only work with a dynamic import() inside reduce, which the browser never evaluates.
split by loader
import { renderThing } from '../lib/views.mjs'      # browser-safe: static import OK

export reduce = (entity, ctx) ->
  mod = await `import('../lib/remote.mjs')`         # server-only: node:, fetch, auth
  mod.resolveThing entity, ctx

export views =
  cell: (entity) -> renderThing entity
The backtick form is embedded JS — CoffeeScript does not parse dynamic import(...) natively. Note a browser-safe lib imported by gate or reduce still needs a server restart: only the browser route stamps mtimes, and Bun caches the server-side import.

§06gate

gate(entity) → boolean

A predicate over the entity — sync or async; the engine awaits it. true = runnable now; false or thrown = parked as idle until another stage fills upstream fields. The engine re-evaluates idle jobs on a 5s sweep and after each merge.

gate patterns
# upstream deps only — don't check "already written"
export gate = (entity) ->
  name = entity.produce?.name
  name? and String(name).trim() isnt ''

# multi-dep example
export gate = (entity) ->
  present = (v) -> v? and String(v).trim() isnt ''
  present(entity.produce?.name) and present(entity.appearance?.color) and present(entity.animal?.name)
Do: check upstream fields you read. Don't: check the field you write — that parks re-plays as idle forever. Idempotence belongs in reduce (return {}).
Engine: src/engine.coffee#_gatePass — loads stage, clones doc, !!await gate(clone). Exceptions → false (idle).
§07reduce

reduce(entity, ctx) → patch

The working end of a stage. Receives a deep-frozen clone of the entity — never mutate it — plus ctx, and returns a partial two-level patch {component: {field: value}}. The engine shallow-merges it, atomically rewrites YAML, and upserts the mirror.

reduce is not a pure function. Side effects are expected: read and write files, call HTTP APIs, shell out, drive an LLM whose tools themselves mutate remote systems. "Pure reducer" was an early design constraint that did not survive contact with real stages — promote-style transporters exist precisely to change the outside world. The frozen entity and the returned patch are the contract; how you arrive at that patch is up to you.
Inputentity is Object.freeze + recursive freeze (src/entities.coffee#deepFreeze). Mutations throw.
OutputPatch object. Missing/empty → no-op. Field values replace wholesale (objects/arrays too). null is a value, not a deletion.
Side effectsAllowed and common. fs, fetch, child processes, authenticated remote writes, and ctx.Agent runs whose tools do all of the above. Pass ctx.signal to anything cancellable so stop/timeout can abort it.
The real rulesDon't mutate the frozen entity. Return the patch rather than writing entity YAML yourself. Make re-play safe (see Idempotence). For irreversible work, refuse before the first remote write and record which guard stopped it.
IdempotenceCheck already set inside reduce and return {} with a ctx.log — keeps re-play cheap.
Errorsthrow new Error '…' to fail the cell (→ error state, durable log). Don't return error objects.
deterministic reduce
export reduce = (entity, ctx) ->
  if entity.appearance?.color? and String(entity.appearance.color).trim() isnt ''
    ctx.log "skip #{entity.produce.name}: appearance.color already set"
    return {}
  name = String(entity.produce.name).toLowerCase()
  color = colors[name] ? fallbackColor(name)
  ctx.log "#{name} → #{color}"
  appearance: color: color

§09patch & merge

Shallow two-level merge

src/entities.coffee#mergePatch — for each component → fields, field values replace wholesale. Dotted field keys are applied via setAtPath (e.g. 'a.b.c': 1 → {a:{b:{c:1}}}).

patch examples
{ appearance: color: '#c0392b' }                 # → doc.appearance.color = '#c0392b'
{ animal: name: 'Capuchin monkey' }             # → doc.animal.name = '…'
{ shipping: 'destination.warehouse': 'east-dock' }  # dotted key → nested set
{}                                              # no-op (idempotent skip)
{ animal: noise: null }                         # null is a value, not deletion
Fields accrue — there is no deletion via patch. To remove a field, edit the YAML or use a dedicated cleanup stage.
§10clear · delete

clear(entity) → patch

Optional export. Called when the user hits Delete/Backspace on a stage cell. Entirely stage-defined — return a patch merged via mergePatch (same semantics as reduce). If absent, Delete falls back to deleting writes[0].

column A — reset to black, keep chrome
# `delete` is reserved in CoffeeScript — use `clear`
export clear = (entity) ->
  appearance: color: '#000000'

# view keeps swatch even when "cleared" — user sees reset, not blank
export views =
  cell: (entity) ->
    color = entity.appearance?.color ? ''
    return template: '<span style="color:#666">—</span>' unless color
    template: """<div class="cell-swatch"><span class="swatch" style="background:#{esc color}"></span><span>#{esc color}</span></div>"""
Nuance: views often show compound chrome (swatches, buttons, charts) that should survive a clear. clear decides what "empty" means — e.g. hex color → #000000 (black swatch stays) vs '' (view shows —). The view must handle both.
Contract: clear is pure, synchronous, no ctx. Return {} for no-op. The server calls it inside POST /api/entities/blank for stage cells; field cells still use deleteAtPath.

§11views

views.cell — the static projection

View functions render into the grid through M.js, the hyperscript/VDOM runtime the Sheets browser app is built on — so whatever template returns must be valid M.js markup, not arbitrary HTML. The browser mounts it via x-html: self-contained static markup with escaped interpolations, no directives, no bindings, no mutations. Behavior and server calls belong in views.mount (§12), not here.

views.cell
esc = (s) -> String(s ? '').replace /[&<>"']/g, (c) -> '&#' + c.charCodeAt(0) + ';'

export views =
  cell: (entity) ->
    v = entity.produce?.volume_inches_cubed
    return template: '<span style="color:#8b8f99">—</span>' unless v? and Number.isFinite Number(v)
    template: '<span class="num-cell">' + esc(Number(v).toFixed(1)) + ' in³</span>'

  # multi-line opt-in — row grows with content (≤500 rows: rows-natural)
  # template: '<div class="cell-tall noise-cell">' + esc(noise) + '</div>'
  • Always escape — template is inserted as HTML.
  • Use class="cell-tall" to opt into multi-line layout.
  • Views do not prove reduce ran — they read persisted YAML only.
  • Structured values: JSON.stringify + escape; never rely on implicit [object Object].
  • Export text(entity) alongside cell — the server evaluates it for column filtering and the "Top values" facet, so computed states stay filterable. Build it as plain(cell…), never as a second hand-written string, or the searchable text drifts from the visible text.
Why views.text is worth the trouble. Derived states — BLOCKED, SUPPRESSED, READY — are computed, never persisted, so without a text projection they are invisible to search and unfilterable. With one, the facet turns the corpus into measured counts: filtering a promote column returned 41 ALREADY_MOVED and 14 SUPPRESSED, independently reproducing numbers that three planning documents disagreed about. Reconcile a plan against the store before trusting the plan.
§12views.mount · live cells

views.mount(el, ctx) — behavior

views.cell is a static string; views.mount is where a cell becomes interactive. It runs after the template is in the DOM, receives the host element and a browser-side ctx, and returns an unmount function. This is the hook that lets a cell call the server — ctx.rpc (§13) and ctx.patchEntity (§14).

interactive cell
export views =
  cell: (entity) ->
    template: """<button class="mv-btn" data-act="resolve">Resolve</button>"""

  mount: (el, ctx) ->
    btn = el.querySelector '[data-act="resolve"]'
    return unless btn
    onClick = (e) ->
      e.preventDefault()
      btn.disabled = true
      try
        await ctx.rpc 'resolve', { force: false }   # → §13
      finally
        btn.disabled = false
    btn.addEventListener 'click', onClick
    -> btn.removeEventListener 'click', onClick     # unmount fn

  onKey: (e, ctx) ->
    return false unless e.key is 'Enter'
    ctx.openEditor key: 'binding', component: 'dataset'
    true                                            # true = key consumed

Remount rule: the grid remounts only when the host node was rewritten (the cell string changed) or the entity under that key changed. Unchanged templates survive ordinary redraws, so mounted widgets and listeners persist — build expensive widgets in mount, not cell.
Always return the unmount. Cells scroll out of the virtual window constantly. A mount that adds listeners, timers, or observers without returning a teardown leaks one set per scroll pass.
§13rpc · view → server → stage

rpc(entity, method, ctx) — user-triggered actions

The escape hatch from the run queue. A view calls ctx.rpc(method, args), the browser POSTs /api/rpc, and the server routes it into your stage's own rpc export — which can do anything: hit a remote API, query a service, compute a proposal. Return a patch and Sheets persists it atomically, exactly like reduce.

export rpc = (entity, method, ctx) ->
  switch method
    when 'resolve'
      remote = await `import('../lib/remote.mjs')`   # server-only, like reduce
      hit = await remote.lookup entity, ctx.args, signal: ctx.signal
      ctx.log "resolved #{hit.id}"
      # returning a patch persists it; message/result go back to the view
      { patch: { dataset: binding: hit.id }, message: "bound → #{hit.id}" }

    when 'list'
      # read-only form — no patch, just data for the view to render
      { result: await remote.listCandidates entity }

    else
      throw new Error "unknown RPC method: #{method}"
Server-side rpc ctx — entityId, activity, source, args, signal, log. Note it is not the reduce ctx: there is no Agent, model, yaml, or onAgent.
Response — { ok, doc, message, result }. The browser swaps in the returned doc, reschedules mounts, and toasts message.

RPC is not a stage run. No gate, no queue, no concurrency limit, no .sheets/runs/ entry — and it may mutate remote systems irreversibly. Keep its controls narrow, state-gated, and clearly named. The operator's click is the confirmation; the agent never invokes one.
§14entity rest api

Mutating entities from a view

Views can edit entity resources directly over REST — no stage run involved. From a mount, ctx.patchEntity(patch) wraps PATCH /api/entity/:id with the desync guard, keepalive, and a local row update so the grid reflects the write immediately.

EndpointMethodEffect
/api/entity/<id>GETReturns { id, doc }.
/api/entity/<id>PATCHmergePatch → atomic YAML write → mirror upsert → engine.pump().
/api/entity/<id>DELETEStops queued cells for every stage, removes the file and the mirror row.
/api/entity/<id>/renamePOST400 invalid id, 409 if the target already exists.
/api/entitiesPOSTCreate entities.
/api/entities/delete
/api/entities/duplicate		POSTBulk operations over a selection.
/api/entities/blankPOSTDelete-key clear. Stage cells call clear (§10); field cells use deleteAtPath.
two accepted PATCH bodies
# 1 — full two-level patch (same semantics as a reduce return, §09)
{ patch: { dataset: { binding: 'orders-v2' } } }

# 2 — single field; `field` may be a nested dotted path under the component
{ component: 'publish', field: 'destination.namespace', value: 'team-alpha' }

# from inside views.mount:
await ctx.patchEntity dataset: binding: 'orders-v2'
A patch can wake the queue. The handler calls engine.pump() after persisting, so writing an upstream field from a view can immediately un-park downstream cells sitting in idle (§06).
Same merge rules apply (§09): values replace wholesale, null is a value rather than a deletion, and there is no delete-by-patch. A desynced client refuses to persist — check ctx.canPersist() before offering the control.

§18llm pattern · required

Structured output via output_tool

CoffeeScript — not JS
export reduce = (entity, ctx) ->
  agent = await ctx.Agent.factory
    model: ctx.model
    system_prompt: """
      You are an expert botanist and geometric analyst.
      Determine the approximate average volume of the specific fruit.
      Return the value in cubic inches.
      <entity>
      #{ctx.yaml entity}
      </entity>
      """
    output_tool:
      name: 'answer'
      description: 'Return the average volume in cubic inches'
      parameters:
        volume_inches_cubed: { type: 'number', description: 'The average volume in cubic inches' }
      required: ['volume_inches_cubed']
      fn: (args) ->
        t = Number args.volume_inches_cubed
        throw new Error 'volume must be a finite number' unless Number.isFinite t
        { volume_inches_cubed: t }
    stream: true
    retries: 0
  ctx.onAgent agent
  out = await agent.run prompt: meta.prompt
  ctx.log "Fruit: " + entity.produce?.name + " -> Volume: " + out.volume_inches_cubed
  produce: volume_inches_cubed: out.volume_inches_cubed
  • ctx.onAgent(agent) is required — it enables stop/timeout abort.
  • fn validates and normalizes tool args; throw on a bad shape.
  • Embed #{ctx.yaml entity} in system_prompt so the model sees the full entity.
  • stream + retries: 0 is the conventional default.
ctx.Agent is AGL (agl-ai). What you are building above is a microagent: a single-purpose agent with a constrained system prompt and exactly one structured output_tool. Before writing an LLM stage, read MICROAGENT.md — it explains how microagents are designed and why the tool schema, not the prose, carries the contract. For a full worked agent, see src/agents/home.mjs. A stage reducer is the smallest possible instance of that pattern: one entity in, one validated value out.

Wiring AGL in this environment

The sheets package already depends on agl-ai and imports it once — import Agent from 'agl-ai' in src/engine.coffee. That exact module object is handed to you as ctx.Agent, so a stage never resolves the dependency itself.

Do not import Agent from 'agl-ai' in a stage or in .sheets/lib/*.mjs. Those files live in the workspace, so a bare specifier resolves against the workspace's node_modules — not the sheets package that actually owns the dependency. It will usually fail outright, and if it resolves it gives you a second Agent class with its own Agent.default and its own concurrency gate. Always go through ctx.Agent; pass it down as an argument if a lib needs it.
ctx.AgentThe default export of agl-ai — the Agent class itself, not an instance.
ctx.Agent.factory{ model, system_prompt, output_tool, tool_choice, context_window_size, parallel_tools, reasoning_effort, max_tokens, stream, on_delta, retain_history, retries } → an agent instance.
agent.Tool(…)(name, description, properties, required, fn) — register a tool the model may call. fn runs for real; this is where a stage legitimately touches the outside world.
agent.run(…)await agent.run prompt: meta.prompt → the validated output_tool result.
ctx.Agent.defaultProcess-wide defaults — .model and .concurrency (1 = serial inference). The engine sets concurrency from the queue slider; don't fight it from a stage.
ctx.modelAlready resolved for this cell: meta.model ?? ws.model ?? Agent.default.model. Pass it straight through.

Models are "provider:model" strings. Providers ship as subpath exports of agl-ai — copilot, xai, ollama, lm-studio, runpod, muse — so 'lm-studio:google/gemma-4-12b-qat' selects the LM Studio provider and that model.

agent with a tool that does real work
export reduce = (entity, ctx) ->
  agent = await ctx.Agent.factory
    model: ctx.model                       # 'provider:model', already resolved
    system_prompt: """
      Price the item below. Call lookup_price before answering.
      <entity>
      #{ctx.yaml entity}
      </entity>
      """
    output_tool:
      name: 'answer'
      description: 'Return the unit price in USD'
      parameters:
        unit_price: { type: 'number', description: 'Unit price in USD' }
      required: ['unit_price']
      fn: (args) ->
        t = Number args.unit_price
        throw new Error 'unit_price must be finite' unless Number.isFinite t
        { unit_price: t }
    stream: true
    retries: 0

  # Tools RUN. This one does network I/O — allowed, and the reason ctx.signal exists.
  agent.Tool 'lookup_price',
    'Look up the current list price for a SKU',
    { sku: { type: 'string', description: 'SKU to price' } },
    ['sku'],
    (args) ->
      res = await fetch "https://pricing.example/api/#{args.sku}", signal: ctx.signal
      throw new Error "lookup failed: #{res.status}" unless res.ok
      (await res.json()).list_price

  ctx.onAgent agent                        # required: lets stop/timeout abort
  out = await agent.run prompt: meta.prompt
  pricing: unit_price: out.unit_price

Import errorDynamic import(url) failure → STAGE_IMPORT — job → error.

§21performance & limits

What to watch

  • Row height: ≤500 rows → rows-natural (auto-expand via .cell-tall); >500 → rows-fixed (uniform ROWH for virtual scroll). Keep ROWH in public/app.js and --rowh in public/styles.css in sync.
  • Module size: very large generated stages can hit Bun's import limit — prefer short helpers.
  • Concurrency: persisted to .sheets/config.yaml; the queue is a single FIFO with a per-entity file lock.
  • Hot reload: stage edits invalidate the cache; the browser re-fetches /stagemod/stages/<slug>.mjs on next render.

export meta =
  title: 'Fruit color'
  prompt: 'Assign the fruit its canonical display color.'
  writes: ['appearance.color']

export gate = (entity) ->
  name = entity.produce?.name
  name? and String(name).trim() isnt ''

export reduce = (entity, ctx) ->
  if entity.appearance?.color? and String(entity.appearance.color).trim() isnt ''
    ctx.log "skip #{entity.produce.name}: appearance.color already set"
    return {}
  name = String(entity.produce.name).toLowerCase()
  color = colors[name] ? fallbackColor(name)

color-fruit-animal-eats-describe.coffee — LLM
export meta =
  title: 'Eating noise'
  prompt: 'Based on the color of the fruit and the animal that eats it , Describe the noise…'
  writes: ['animal.noise']

export gate = (entity) ->
  present = (v) -> v? and String(v).trim() isnt ''
  present(entity.produce?.name) and present(entity.appearance?.color) and present(entity.animal?.name)

export reduce = (entity, ctx) ->
  if entity.animal?.noise? and String(entity.animal.noise).trim() isnt ''
    ctx.log "skip #{entity.produce?.name}: animal.noise already set"
    return {}
  agent = await ctx.Agent.factory
    model: ctx.model
    system_prompt: """
      You are an imaginative writer. Based on the animal, the fruit, and the specific color…
      <entity>
      #{ctx.yaml entity}
      </entity>
      """
    output_tool:
      name: 'answer'
      description: 'Return the noise description'
      parameters: { noise: { type: 'string', description: '1-2 sentence description' } }
      required: ['noise']
      fn: (args) ->
        t = String(args.noise ? '').trim()
        throw new Error 'noise must be non-empty' unless t.length > 0
        { noise: t }
    stream: false
    retries: 0
  ctx.onAgent agent
  out = await agent.run prompt: meta.prompt
  animal: noise: out.noise
§23best practices

Lessons from stages that shipped

Field notes from building real columns against a ~1,000-entity corpus. Most of this is non-obvious and was learned by breaking something.

Who presses Play

Stage execution belongs to the human operator. An AI assistant working in this repo may read stage source, activity YAML, entity files and run logs; edit stage code and configuration on request; compile CoffeeScript statically; and read non-executing HTTP metadata/view endpoints. It must not click Play or Run selection, call /api/run, /api/run/range or /api/dry-run, run sheets run/sheets stop, import a stage module to invoke gate/reduce/rpc directly, or treat a rendered view as proof that a reducer ran. A stage result is not real until the operator confirms it from the UI or the run log.

Keep stages thin — logic lives in libs

A stage file should be the contract exports plus call-throughs. Real logic goes in .sheets/lib/, split by which loader evaluates it (§03):

FileLoaderMay use
.sheets/lib/<domain>.mjsserver only — dynamic import() inside reducenode:*, fetch, credentials, fs
.sheets/lib/views.mjsbrowser + server — static importDOM-safe JS only; every renderer
.sheets/lib/cell.mjsbrowser + server — static importescape / display / badge helpers
.sheets/stages/<slug>.coffeebothmeta / gate / reduce / views only

The gate and the cell must share ONE eligibility function

A cell that says "run me" for a row the gate silently parks as idle is the most confusing failure in the grid — nothing errors, nothing happens. Put the predicate in one pure, browser-safe lib function and let both sides consume it.

one predicate, two consumers
# lib/views.mjs — returns { eligible, status, reason }
import { promoteEligibility } from '../lib/views.mjs'

export gate = (entity) -> promoteEligibility(entity).eligible

export views =
  cell: (entity) ->
    { status, reason } = promoteEligibility entity
    template: "<span>#{esc status} — #{esc reason}</span>"
One place to change, and the two can never disagree. Corollary: an ineligible cell should name its blocker — SUPPRESSED — duplicate of an existing target — and link the evidence. "Not run yet" is a lie when the gate will never admit it.

Know which of the three kinds of stage you are writing

KindWritesExample
Proverentity evidence onlyproves a field is valid and records the proof
Repairerthe staged remote objectapplies the proven decision to the real object
Transportermoves the objectpromote copies staging → target
The trap: a prover writing evidence: ok changes nothing remote. A transporter that faithfully copies the staged object will happily ship the old value, and the entity will claim one thing while the live object does another. Decide explicitly which stage applies a decision — otherwise every column is individually correct and the pipeline is still wrong.

Classify infrastructure failures separately from semantic ones

A 401, a timeout, or an empty result must never be recorded as "the field is missing." Give it a distinct status — UNVERIFIED — so a stale credential doesn't send someone off to fix a value that was never broken. Deterministic-first, and let verdicts stay honest; that is the whole value of the grid.

Resolve remote dependencies by semantics, never by id

The same logical object usually exists under a different id in every namespace. Matching by id creates duplicates; matching by meaning finds the one that is already there.

match, then remap references
hit = await findByMeaning target, pattern, reviewedKey
if hit.found
  remap.set dep.id, hit.found.id     # reuse it; import nothing
# rewrite references[] through `remap` before importing anything

Write every receipt key on every run

Patches merge per field (§09), so any key a later run does not write survives from the previous run. A REFUSED receipt once inherited import_errors from an earlier FAILED run and looked like both had happened. Emit the full key set with null/[] defaults, then spread the run's evidence over it.

Irreversible stages need an explicit commit boundary

  • Do every refusal before the first remote write, and record which guard stopped it (a step field) so a refusal is attributable to one operation.
  • Keep the destructive tail behind an env flag until the proof actually justifies it.
  • Don't let a structural check masquerade as a behavioural one. Readback + reference closure + item census proves the shape rendered, not that it works. Name the proof kind in the receipt.
  • When a write succeeded but proof failed, return a distinct status (PARTIAL), never delete the source, and list the created objects for reconciliation.

Model configuration

Resolution order is meta.model → .sheets/config.yaml → $FAV_LOCAL_LLM → AGL default (§05). Prefer setting FAV_LOCAL_LLM in your shell rc over pinning a model in files — a pinned meta.model outlives its usefulness and silently overrides everyone else's choice. The chat model dropdown is the union of the agent definition's models array, its model, the active model, the workspace model, and $FAV_LOCAL_LLM; a model absent from all of those will not appear.
